## 3.1 产品调性关键词

**月光、温柔、被拥抱、低饱和、像深夜的一盏小灯**

> 来源：[BRD.md](../BRD.md) §1（凌晨独自崩溃 + 私密被接住的核心叙事）+ 用户对话 Q2 拍板

补充说明：调性的最大反例是"明亮活泼"和"神秘塔罗暗黑感"。前者对扛家用户的处境是不敬，后者会盖掉"被接住"这层情绪陪伴的核心价值。

## 3.2 目标用户视觉感受

- **打开瞬间应感受到**：像深夜独自走进一个安全的、灯光柔和的小房间，没有人评判你，可以放下肩膀
- **使用场景**：90% 是凌晨/深夜独处场景，手机竖屏单手操作；少数白天通勤碎片时间；几乎不会出现在多人/办公室/高光环境

## 3.3 目标市场与语言

- **主市场**：泰国
- **主语言**：`th`（泰语）
- **多语言切换**：不需要（V1 仅泰语）。中文/英文切换是 V3 之后的事
- **特殊字族要求**：必须支持泰语显示——design-spec 阶段需指定具体的 Noto Sans Thai / IBM Plex Sans Thai / Sarabun 等泰语字族（具体选哪个由 design-spec 决定）。**正文长开示 200-400 字**的泰语阅读舒适度是关键考量

## 3.4 参考竞品 / 灵感方向

| 竞品/参考 | 借鉴什么 | 不借鉴什么 |
|---------|---------|-----------|
| Calm（冥想 App）| 暮色温柔的渐变氛围、卡片柔和投影、低饱和色板 | 它的订阅付费引导（我们押单次打赏） |
| Replika（AI 陪伴）| 输入区的安全感、对"私密性"的视觉表达 | 它的拟人化头像 / Avatar 概念 |
| Headspace | 圆润几何、动效克制的呼吸感 | 它的明亮卡通插画风（与扛家用户处境违和） |
| 泰国寺庙 / 月光夜景 | 文化场景中"寺庙夜灯""月色"的氛围语言 | 直接的宗教符号（佛像/经文）—— 避免冒犯 |

## 3.5 必备的视觉约束（硬性要求）

- [ ] **必须支持暗色为主**——使用场景 90% 是夜间，亮色版可作为日间备选但暗色是主形态
- [ ] **必须考虑可访问性**：WCAG AA 对比度（用户 30-55 岁，正文 200-400 字阅读时间长）；提供大字号选项（design-spec 可以决定具体方案）
- [ ] **必须避免**：
  - 高饱和警示红/亮黄等"刺激色"作为主色或大面积色块
  - 直接的佛像/经文/明确宗教符号（避免冒犯佛教文化）
  - 卡通化插画 / 拟人 Avatar（与扛家用户的成人重负处境违和）
  - 闪烁、强烈动效、自动播放视频/音频（凌晨场景禁忌）
- [ ] **必须传递的核心感受**：**安全感、不被评判、被接住、有人在听**——这是产品价值根基，任何视觉决策不能违背这四个词
- [ ] **必须避免误导付费**：打赏区块的视觉重量必须**轻于**开示正文；不能用任何"未付费看不全"的暗示样式（第二段开示糊化、付费弹窗等都禁用）

## 3.6 组件清单的视觉密度提示

> 这一节给 design-spec 一个组件密度的初步暗示——具体样式由 design-spec 定，本节只描述"密度倾向"。

来自 [04-pages-components.md](./04-pages-components.md) 的页面/组件初步清单：

| 页面/组件 | 信息密度 | 操作密度 | 视觉重点 |
|---------|---------|---------|---------|
| 首页（Landing） | 极低（一句邀请 + 一个按钮） | 极低 | 暮色氛围、邀请文案的呼吸感 |
| 抽牌页（CardDraw） | 极低（1 张牌 + 短描述） | 极低（点击翻牌） | 翻牌的仪式感、牌面的氛围 |
| 倾诉页（ConfessTextarea） | 低（一个大文本框 + 字数提示 + 隐私徽章） | 低（输入 + 提交） | 输入区的安全感、隐私徽章可见但不突兀 |
| 开示展示页（StreamingReading） | 中（200-400 字泰语正文 + 文末打赏区） | 低（阅读为主） | **正文阅读舒适度第一**，打赏区块视觉权重轻 |
| 危机干预（CrisisGate） | 低（一段温柔说明 + 1323 热线 + 一个返回按钮） | 极低 | 不冰冷、不像错误页 |
| 打赏区块（DonateBlock） | 低（3 个金额按钮 + PromptPay QR） | 中（选额 + 唤起 QR） | 金额按钮平等并列，无大小差异、无"推荐选项"高亮 |
| 结束页（Done） | 极低（感谢 + 重新开始） | 极低 | 收尾的温度，不强行留人 |

> 注意：本表的"页面/组件"只是初步占位。完整列表以 [04-pages-components.md](./04-pages-components.md) 为准——design-spec 会读 04 那份。

## 3.7 design-spec 必须回答的问题（输出契约）

design-spec 在产出 `DESIGN.md` 时必须覆盖以下条目，否则视为 handoff 不完整：

- [ ] 完整色板（含暗色为主形态的全部 hex 值）
- [ ] 字体系统：含**泰语字族**的具体 Google Fonts URL 或 next/font 引入方式；正文 / 标题 / 数字三档字阶
- [ ] 间距与圆角的统一栅格（基准由 design-spec 决定，常见选择是 4 或 8 单位制）
- [ ] 动效规范：默认 L1 静态优雅；翻牌动效与流式文字打字动效是仅有的两个允许的强动效，需明确曲线和时长
- [ ] 组件基础样式指引（按本文件 §3.6 列出的 7 类组件给样式）
- [ ] 暗色模式（必出，且为主形态；亮色模式可选作为日间备选）
- [ ] 大字号可访问性方案（30-55 岁用户长文本阅读必备）
